# WebP 素材迁移计划

## 问题背景

当前页面直接引用多张 JPG、PNG、JPEG 素材，图片体积较大，首屏和翻页时存在额外加载压力。用户希望在不改变页面内容和视觉素材的前提下，使用 WebP 以降低传输体积并提升渲染速度。

## 现有结构分析

- 图片素材集中在 `assets/` 目录。
- 图片路径分散在 `index.html`、`deck.css`、`styles.css`、`complete.css` 和 `script.js`。
- 页面依赖文件名映射兵种、技术组、背景和演示页，因此不能仅批量改扩展名，必须同步检查所有引用。

## 修改计划

1. 统计实际被页面引用的栅格图片及其格式。
2. 使用本地可用的 WebP 转换工具生成同名 `.webp` 素材，保留原始文件作为回退和素材存档。
3. 将代码中的图片引用迁移到 `.webp`，不修改文案、页面顺序和图片对应关系。
4. 检查 WebP 文件完整性、页面图片加载状态、桌面端和移动端布局溢出。
5. 提交并推送到 GitHub Pages，验证线上入口返回正常。

## 潜在影响

- 浏览器请求路径改变，需要确认所有引用都已更新。
- 原始素材继续保留，因此仓库总大小不会立刻下降，但页面运行时将优先加载 WebP。
- 若个别素材无法转换，将保留原格式并报告，不替换为内容不同的图片。

## 验证方式

- 使用文件扫描确认页面代码不再引用应迁移的旧格式。
- 浏览器检查所有图片 `complete === true` 且 `naturalWidth > 0`。
- 在 1440×900 和 390×844 下检查页面无横向或纵向溢出。
- 访问 GitHub Pages 确认部署成功。
